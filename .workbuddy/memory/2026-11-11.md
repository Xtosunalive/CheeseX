## 口径纠正（01:53）：SSH 推送坏了应修根因，不该改 remote 绕路

- 用户质疑「坏了不应该修吗」成立，撤回上轮「把产品仓 remote 改成 HTTPS」的主推。实测：remote 保持 `ssh://git@ssh.github.com:443/Xtosunalive/CheeseX.git` 即可用。
- 根因定位：`~/.ssh/config` 的 `Host ssh.github.com` 用 `ProxyCommand python3 ~/.ssh/git-ssh-connect-proxy.py %h %p`；该脚本只读 `GIT_SSH_HTTP_PROXY`，**缺省回落写死的 `127.0.0.1:57621`**，而该端口无监听者。当前环境实际代理是 `HTTPS_PROXY=http://127.0.0.1:49343`（WorkBuddy 会话注入，端口每次会变），变量没接上。且 `ssh -o ProxyCommand=none` 直连两次均成功 → 那层代理本就不是必需。
- 修法：只改 `~/.ssh/git-ssh-connect-proxy.py`（config 与 remote 一字未动）。新增 resolve_proxy()：按 GIT_SSH_HTTP_PROXY → HTTPS_PROXY/https_proxy → ALL_PROXY/all_proxy 解析，去 scheme、去 user@；新增 open_via_proxy()/connect()，代理缺失/不可达/拒绝 CONNECT 时 warn 后**自动回落直连**；彻底删除硬编码 57621。
- 备份：`~/.ssh/git-ssh-connect-proxy.py.bak-20261111-0148`（原 2515 字节，755）。回滚：`cp -p <bak> ~/.ssh/git-ssh-connect-proxy.py`。
- 实测：compile 语法 ok；A 默认环境（自动用 49343）、B 清空全部代理变量（直连兜底）、C 变量仍指死端口 57621（warn 后回落直连）三场景 `ssh -T` 均返回 `Hi Xtosunalive!`；`git push --dry-run origin main` exit=0 `Everything up-to-date`；remote、~/.ssh/config、仓库工作区均未变；无 pycache 产物。
- 结论：默认 `git push` 已恢复，无需改 remote；以后本地代理端口随会话变化也不会再断。真正提供 57621 的外部程序未启动、也无法由本席启动，但已不再依赖。
- 工具坑：macOS BSD grep 不认 GNU 的 `\|`，诊断时误以为 ~/.ssh/config 无内容；应改用 `grep -E "A|B"`。
